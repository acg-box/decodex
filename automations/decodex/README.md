# Decodex Content Automations

The exact-five portfolio contains two content roles. Their source definitions
are in `automations/portfolio.toml`; this directory contains their prompts,
compact validation code, and Publisher schemas.

## Content Manager

The Content Manager is an autonomous editor. It researches:

1. official OpenAI Codex releases, documentation, source, and protocol changes;
2. landed Decodex changes and their verified user or operator consequences;
3. CodexRadar only as secondary discovery or editorial input.

CodexRadar cannot be the only evidence for a factual claim. A candidate must
contain at least one `official_codex` or `landed_decodex` source.

Each run decides whether one useful, non-repetitive post is justified. It writes
one private staging document with schema `decodex/content-evidence/1`, or writes a
`no_op` decision with an evidence-backed reason. It then invokes exactly one
deterministic write boundary:

```sh
decodex-publisher social record-candidate \
  --staging <private-json> \
  --run-id "$CODEX_THREAD_ID"
```

The boundary validates source quality, claims, text, account, and backpressure.
It inserts the immutable `content-publication:<sha256>` identity, writes the
candidate atomically with mode `0600`, reads it back, and removes staging. At
most one unresolved candidate can exist.

There is no content queue, pair, impact review, eligibility receipt, strategy
store, review committee, activation marker, or migration reader.

## Evidence Contract

A recorded candidate has:

- target account `decodexspace` and channel `x`;
- exactly one post text with 80 to 260 weighted characters and no URL;
- one to eight HTTPS source URLs;
- one evidence class for each source URL;
- at least one official Codex or landed Decodex source;
- claims whose evidence exactly matches a declared URL;
- a `publish` or `no_op` decision and a concrete reason;
- an immutable content identity generated by Publisher.

Generated evidence stays under
`.agent/automations/decodex/cache/social`. It is private runtime state and must
not be committed or uploaded.

## Xurl Publisher

The Xurl Publisher performs the final editorial check. It does not hand-run
reservations, ledgers, or recovery steps. It uses two high-level commands:

```sh
decodex-publisher social publish-next \
  --run-id "$CODEX_THREAD_ID" \
  --decision publish

decodex-publisher social observe-due \
  --run-id "$CODEX_THREAD_ID"
```

`publish-next` selects the oldest pending candidate, recovers one interrupted
effect when possible, applies skip or publish, reserves budget, verifies the X
identity, invokes xurl, and performs exact post readback. `observe-due` selects
at most one due 24-hour or 7-day result and performs the bounded read. Missed
outcomes remain due after machine or app downtime.

The Publisher is the only process that can invoke xurl. Browser control, X MCP,
and direct X API calls are forbidden.

## X Safety Roots

The clean cut preserves these hard boundaries:

- sealed OAuth evidence for xurl app `default` and account label
  `decodexspace`;
- paid identity proof for exact author `@decodexspace` before create;
- one post per UTC day;
- no URL or link-like text;
- a `$1.25` shared monthly reserved-cost cap;
- a `$0.030` normal publish ceiling;
- exact post ID, author, and text readback;
- no create retry after an unknown write result;
- immutable attempt journal and budget ledger;
- one bounded 24-hour and one bounded 7-day outcome read per post.

An unknown create result is the one publication state that needs human
reconciliation. Quality failure is an autonomous skip. Missing OAuth is an
external setup blocker.

## Cost Reporting

The checked-in pricing policy reserves at most 30,000 micro-USD for a normal
publish and 5,000 micro-USD for each outcome observation. Before paid work,
inspect readiness and current monthly limits:

```sh
decodex-publisher social refresh-pricing
decodex-publisher social probe-xurl
decodex-publisher social cost-report
```

`refresh-pricing` makes one bounded request to the exact official documentation
URL and makes zero X API calls at zero X API cost. It renews the private pricing
receipt only after strict table parsing. Parser or rate drift blocks paid work.

The cost report uses the immutable local ledger. It reports call counts, used
and reserved ceilings, the monthly cap, and the remaining ceiling. It does not
estimate model cost because the repository has no authoritative model price.

## Validation

```sh
cargo test -p decodex-publisher
cargo clippy -p decodex-publisher --all-targets --all-features -- -D warnings
decodex-publisher validate-social
```

The Rust tests use a fake xurl binary. They verify duplicate and daily limits,
account mismatch, exact readback, monthly budget exhaustion, uncertain-create
non-retry, candidate quality, and 24-hour and 7-day observation behavior without
calling X.
